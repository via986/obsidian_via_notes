создание ключа
`ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_ed25519_my_new_server"`

Команда `ssh-keygen -t ed25519` создаёт ключ с использованием современного алгоритма Ed25519 (на основе эллиптических кривых), в то время как (`-t rsa -b 4096`) использует классический алгоритм RSA с длиной ключа 4096 бит.

Внутри самого SSH-ключа логин (имя пользователя) не зашивается.
SSH-ключ — это просто криптографическая пара (случайный набор символов и математических алгоритмов), которая служит только для проверки вашей цифровой подписи. Сам по себе ключ никак не привязан к конкретному имени пользователя ни на вашем компьютере, ни на сервере.

Откройте файл конфигурации в блокноте

`notepad "$env:USERPROFILE\.ssh\config"`

Добавьте туда настройки для вашего сервера:
`Host my-server`
    `HostName IP_адрес_вашего_VDS`
    `User root`
    `IdentityFile ~/.ssh/id_rsa_my_new_server`

**SSH-тунель**
ssh -D 1080 -N -C user@your-server-ip

Эта команда превращает обычное SSH-подключение к удалённому серверу в локальный SOCKS5-прокси.

Принцип работы: SSH-клиент открывает на вашем компьютере локальный порт, слушает входящий трафик и перенаправляет его по зашифрованному SSH-туннелю на удалённый сервер. Удалённый сервер выполняет сетевые запросы от своего имени и возвращает ответ обратно.
Разбор ключей команды

    -D 1080 (Dynamic application-level port forwarding):

    Ключевой параметр. Запускает локальный SOCKS-сервер на порту 1080 (слушает интерфейс 127.0.0.1). В отличие от обычного проброса портов (-L), где вы привязаны к одному конкретному хосту и порту назначения, динамический проброс умеет маршрутизировать соединения к любым сайтам и портам.

    -N (No remote command):

    Указывает SSH не открывать удалённый командный шелл (терминал сервера). Сессия просто держит соединение открытым. Полезно при создании туннелей, чтобы случайно не закрыть сессию или не выполнять лишних процессов на сервере.

    -C (Compression):

    Включает сжатие потока данных (gzip) на лету. Полезно на медленных соединениях для текста, но создаёт небольшую нагрузку на процессор. Для быстрого канала или передачи бинарных файлов (видео, архивы) флаг можно опустить.

    user@your-server-ip:

    Стандартный логин и IP-адрес вашего удалённого сервера.

Что происходит «под капотом»

    Создание туннеля: SSH-клиент подключается к your-server-ip, проходит аутентификацию (по ключу или паролю) и создаёт защищённый TLS/SSH-канал.

    Запуск слушателя: Клиент открывает сокет 127.0.0.1:1080 прямо в вашей локальной операционной системе.

    Обработка запроса: Когда программа (например, curl или браузер) стучится в 127.0.0.1:1080 по протоколу SOCKS5:

        Программа сообщает прокси: «Соедини меня с api.telegram.org:443».

        SSH-клиент пакует этот запрос в зашифрованный пакет SSH и шлёт его на ваш VPS.

        Демон sshd на сервере расшифровывает пакет, сам устанавливает обычное TCP-соединение с api.telegram.org:443 и гонит трафик обратно в туннель.

Для вашего провайдера весь этот обмен выглядит как один непрерывный зашифрованный SSH-поток на порт 22 вашего сервера. Ни доменные имена, ни конечные IP-адреса сайтов снаружи не видны.
Как запустить в фоновом режиме

Если запустить команду как есть, терминал останется заблокированным до нажатия Ctrl + C. Чтобы запустить туннель в фоне, добавьте ключ -f:
Bash

ssh -f -N -D 1080 user@your-server-ip

    -f заставит процесс уйти в фон сразу после успешной аутентификации.

Чтобы закрыть такой фоновый туннель позже:
Bash

pkill -f "ssh.*-D 1080"
