В корне вашего проекта создается папка `.devcontainer`, а в ней — файл конфигурации `devcontainer.json`. В этом файле вы описываете:

- Какой образ операционной системы использовать (например, Ubuntu).  
- Какие инструменты и расширения для редактора должны быть предустановлены автоматически.    
- Какие порты нужно пробросить наружу (например, чтобы вы могли открыть `localhost:3000` в браузере своего компьютера).

Когда вы открываете эту папку, редактор под капотом запускает Docker, разворачивает окружение и «пробрасывает» ваш исходный код внутрь. Вы получаете терминал, который находится внутри Linux-контейнера, но пишете код в своем привычном и быстром интерфейсе на хост-машине.

Пример:

`{`
  `"name": "My AI Dev Environment",`
  `// Используем готовый официальный образ Ubuntu от Microsoft с предустановленным Git`
  `"image": "mcr.microsoft.com/devcontainers/base:ubuntu",` 

  `// Сюда можно автоматически установить нужные языки программирования`
  `"features": {`        
    `"ghcr.io/devcontainers/features/python:1": {}`
  `},`

  `// Автоматические настройки для Zed внутри контейнера`
  `"customizations": {`
    `"zed": {`
      `// Расширения, которые Zed должен активировать внутри контейнера`
      `"extensions": ["html"]`
    `}`
  `}`
`}`

"переделка" контейнера

`docker update --restart always open-webui`
`docker update --restart no open-webui`

### Как проверить, изменилось ли что-то?

Чтобы убедиться, что настройка применилась, можно заглянуть в свойства контейнера:
Bash
```
docker inspect open-webui --format "{{.HostConfig.RestartPolicy.Name}}"
```
Команда вернет `always` или `no` в зависимости от того, какой режим вы выбрали последним.
